通俗聊算法系列——哈希表

hello,各位好啊，欢迎来到通俗聊算法系列，本系列致力于用通俗易懂的语言为大家讲解算法中常用的一些数据结构或者方法，今天来聊——**哈希表**。

在聊哈希表之前，先问大家一个问题，各位是怎么在一堆快递里精准的找到自己的快递的呢？旁白：你这不废话嘛，我顺着取件码不一下就找着了。对喽，哈希表也是这个道理，具体怎么个事，还请听我细细道来。

关于哈希表，有两个核心概念：**键**和**值**，诶，那就有懂算法的小伙伴要问了，主播主播，哈希函数去哪了？哈希函数我个人在平时使用时并没有什么存在感，这个东西更多是关于哈希表的底层原理的，大部分时候不知道它也不影响使用哈希表，所以我准备把它放到后面再讲，好了，言归正传，让我们继续聊键和值。

**键**，就好像你取快递时用的取件码，帮你快速定位你的快递在什么位置。

**值**，就好像你的快递，只要你拿着取件码，也就是键，就可以快速方便的对值进行增删改查的操作。

在哈希表中，一个键只能对应一个值，就像一个取件码只能对应一个快递一样，一个值可以有多个键对应，但别误会，不是多个取件码可以对应一个快递，而是更类似于你和舍友都买了同一个品牌同一个口味的一箱干脆面，取件码对应的快递是一样的，都是某某品牌某某口味的干脆面，但实际上是两个取件码对应了各自独立的两箱方便面。

接下来聊聊哈希表在算法中的作用，具体作用有好多，比如快速查找，统计频率，计数之类的，我就不详细聊这个了，聊点我认为比较核心的东西，我认为哈希表在算法中的**主要**作用是**空间换时间**，通过牺牲一些空间复杂度，来获取更优秀的时间复杂度，将原本需要多层嵌套循环来完成的操作降级至单层循环+键值对查找来完成。

ok，最后了，来聊聊哈希表的最后一个概念：**哈希函数**，不过先不具体聊哈希函数，先聊点别的，哈希表为什么查找那么快呢？有人就要说了：你不是刚说过吗，键值对啊，用键找值，当然快啊。对，说的没错，不过我想说的是更底层的原因，哈希表底层其实也是数组，不过哈希表会将键转为一个数组索引，然后将值存在数组的那个位置，所以通过键找值时就会直接到那个位置获取那里储存的值，当然就快了。而要将键转为数组索引，就离不开哈希函数。

不同的语言对于哈希函数的实现不同，我就简单讲一下大致思路，分为两步：

第一步：将原本类型各异的键，统一转为一个整数。

第二步：因为哈希表内部的数组大小有限，因此需要将这个整数映射到哈希表内部的数组索引中。

经过以上两步处理，键就被转为了数组索引，不过这也引出了另一个问题：**哈希冲突**，因为哈希表内部数组的大小是有限的，如果有两个不同的键被映射到同一个位置该怎么办，对于这个问题，有两种主流的解决方法：**拉链法**和**开放寻址法**。

拉链法：使用拉链法解决这个问题时，数组储存的就不再是元素了，而是一个个链表，关于链表，之后也会写一篇文章来介绍，新增只需要知道链表是一种像手串一样按连接顺序储存数据的数据类型即可。当相同索引的元素出现时，直接将新元素挂到链表最后，查找时逐个比较链表中元素的键来查找，在 Java 和 Python 中当链表长度超过阈值时还会将链表转为红黑树来提高查找效率，红黑树我应该是不会出文章来讲，感兴趣的朋友可以自行查找相关资料。

开发寻址法：这种方法不额外添加其他数据结构，依旧是将所有元素储存在哈希表数组中，当出现哈希冲突时，使用不同的探测方法去找写一个空闲位置，然后将数据保存在空闲位置中，常用的探测方法有线性探测法，二次探测法和双重散列，本来想聊聊这三种方法的实现和缺点来着，不过哈希函数部分写的已经没那么通俗了，再加上这些，一多半都是比较学术的内容了，就到这里吧。
