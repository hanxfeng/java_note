- # CAS

	```java
	// AtomicInteger 是一种特殊的包装类
	private AtomicInteger balance;
	
	Thread t1 = new Thread (() -> {
		while (true) {
			int prev = balance.get(); // 原始值
			int next = prev - 10; // 修改值
			if (balance.compareAndSet(prev, next)) {
				break;
			}
		}
	})
	```
	
	- 这样可以实现无锁保护共享资源的线程安全，核心在于 compareAndSet 上，简称 CAS，是原子操作，其原理是比较输入的原始值与当前值是否相同，如果相同修改为修改值返回 true，否则返回 false，这样就可以避免多个线程同时调用时出现混乱
	  
	- CAS 需要借助 volatile 才能读取到共享变量的最新值来实现比较并交换的效果
	
	- # 为什么 CAS 的效率高于加锁
	  
		- 无锁情况下，即使重试失败，线程也始终在高速运行，没有停歇，而 synchronized 会让线程在没有获得锁的时候发生上下文切换，进入阻塞状态
	
	- ## CAS 特点
	  
		- CAS 基于乐观锁思想，不怕别的线程修改变量，就算变量被修改了，再进行重试即可
		  
		- synchroized 基于悲观锁思想，防着其他线程来修改变量，必须在我修改完之后才能交给其他线程修改
		
		- CAS 适用于线程数较少，多核 cpu 的条件下


- # 原子整数
  
	- 包括 AtomicInteger，AtomicBoolean，AtomicLong
	  
	- 这些对这些包装类的值进行修改时，都是原子的
	  
	- ## 以 AtomicInteger 为例
	  
		- `i.getAndIncrement`：先获取当前值，再使当前值自增 1
		  
		- `i.IncrementAndGet`：先使当前值自增 1，再获取自增后的值
		  
		- `i.getAndDecrement`：先获取当前值，再使当前值自减 1
		  
		- `i.decrementAndGet`：先使当前值自减 1，再获取自减后的值
		  
		- `i.getAndAdd(int n)`：先获取当前值，再使值自增 n
		  
		- `i.addAndGet(int n)`：先使值自增 n，再获取自增后的值
		  
		- `i.updateAndGet(lambda)`：传入一个 lambda 或匿名内部类，在其中对数据进行处理，`i.updateAndGet(x -> x * 5);` ，先更新再获取
		  
		- `i.getAndUpdate(lambda)`：同上，先获取再更新


- # 原子引用
  
	- 原子引用类型包括以下几种：AtomicReference，AtomicMarkableReference，AtomicStampedReference
	  
	- 原子引用类型出现的目的是为了保护非基本类型的数据，例如 BigDecimal
	  
	- `balance = new AtomicReference<>(balances);`：创建一个 AtomicReference 对象（假设 balances 是已经创建好的 BigDecimal 数据）
	  
	- `balance.compareAndSet(prev, next);`：如果 prev 的值与 balance 的值相同，那么将 balance 的值更改为 next
	  
	- ## ABA 问题
	  
		- 在调用 compareAndSet 时，它并不能感知到原本的数据有没有被修改过，例如，先调用 get 方法获取 prev，然后此时另一个线程先将变量值从 A 改到 B，再从 B 改到 A，然后再调用 compareAndSet 方法，是可以正常运行的，当然，这个问题大部分时候是没有影响的
	
	- ## AtomicStampedReference
	  
		- 为了解决 ABA 问题，可以使用 AtomicStampedReference，在创建对象时会引入一个版本号，每次对变量修改后使版本号 +1，在修改时，不仅要值相同，还要版本号相同
		  
		- 示例
		```java
		AtomicStampedReference<String> ref = new AtomicStampedReference<>("A", 0);
		String prev = ref.getReference();
		int mstamp = ref.getStamp();
		ref.compareAndSet("A", "B", mstamp, mstamp+1);
		```
	
	- ## AtomicMarkableReference
	  
		- 与 AtomicStampedReference 相比，不再使用版本号来标记变量的修改次数，而是使用 true 或 false 标记变量有没有被修改过
		  
		- 示例：
		```java
		AtomicMarkableReference ref = new AtomicMarkableReference<>("A", true);
		String prev = ref.getReference();
		// 第三个参数是原来的标记，第四个参数是新标记
		ref.compareAndSet(prev, "B", true, false);
		```
