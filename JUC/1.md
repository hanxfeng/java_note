- # 进程与线程
  
	- ## 进程
	  
		- 程序由指令和数据构成，但这些指令要运行，数据要读写，就必须将指令加载至 cpu，数据加载至内存，在指令运行过程中还需要用到磁盘，网络等设备。进程就是用来加载指令，管理内存 IO 的
		  
		- 当一个程序被运行，从磁盘加载这个程序的代码至内存，这就开始了一个进程
		  
		- 进程可以被视为一个程序的实例，大部分程序可以同时运行多个进程
	
	- ## 线程
	  
		- 一个进程之内可以分为一到多个线程
		  
		- 一个线程就是一个指令流，将指令流中的一条条指令以一定顺序交给 cpu 执行
		
		- Java 中，线程是最小调度单位。进程作为资源分配最小单位，在 Windows 进程中是不活动的，只是作为线程的容器
	
	- ## 同步
	  
		- 需要等待结果返回，才能继续运行，这就是同步
	
	- ## 异步
	  
		- 不需要等待结果返回，就可以继续运行，这就是异步


- ## 创建线程
  
	- ## 直接使用 Thread 创建
	```java
		// 传入的 t1 是线程名，可以不加，但推荐加入
		Thread t = new Thread("t1") {
			@Override
			public void run() {
				// 需要执行的代码
			}
		}
		// 启动线程
		t.start();
	```  
	
	- ## 使用 Runnable 配合 Thread
	```java
		// 创建 Runnable
		Runnable runnable = new Runnable() {
			@Override
			public void run() {
				// 要执行的代码
			}
		}
		
		// 创建 Thread 并执行
		Thread t = new Thread(runnable);
		t.start();
	```  
	
	- 因为是使用匿名内部类重写，因此可以使用 lambda 表达式进行简化
	
	- ## FutureTask 配合 Thread
	```java
		// 创建任务对象，lamdba 简化版
		FutureTask<Integer> t = new FutureTask<>(() -> {
			// 要执行的代码
			return 100;
		});
		
		// 完整版
		FutureTask<Integer> t = new FutureTask<>(new Callable<Integer>(){
			@Override
			public Integer call() throws Exception{
				//要执行的代码
				return 100;
			}
		})
		
		// 参数 1 是任务对象，参数 2 是线程名字
		new Thread(t, "t").start();
		
		// 
		Integer resulr = t.get();
	```


- # 栈与栈帧
  
	- JVM 中由栈、堆、方法区构成，栈内存分配给线程使用，每个线程启动后虚拟机都会为其分配一块栈内存
	  
	- 每个栈由多个栈帧组成，对应着每次方法调用时所占用的内存
	  
	- 每一个线程只有一个活动栈帧，对应着正在执行的方法


- # 线程上下文切换
  
	- 以下原因会导致 cpu 不再执行当前线程转而执行另一个线程的代码
	  
		- 线程的 cpu 时间片用完
		  
		- 垃圾回收
		  
		- 有更高优先级的线程需要执行
		  
		- 线程自己调用了 sleep yield join 等方法
	
	- 当 上下文切换 发生时，需要由操作系统保存当前线程的状态，并恢复另一个线程的状态， Java 中对应的概念就是程序计数器，它的作用是记住下一条 JVM 指令的地址，是线程私有的
	
		- 状态包括，程序计数器，虚拟机栈中每个栈帧的信息，如局部变量，操作数栈，返回地址等
		  
		- 上下文切换频繁发生会影响性能


- # 常见方法
  
	- ## start 和 run
	  
		- ### start
		  
			- 启动一个新线程，在新的线程运行 run 方法中的代码
			  
			- start 方法只会让线程就绪，不一定立刻运行，每个对象只能调用一次 start 方法，调用多了会报错
		
		- ### run
		  
			- 新线程启动后会调用的方法
			  
			- 如果在构建 Thread 对象时传递了 Runnable 参数，则线程启动后会调用 Runnable 中的 run 方法，否则默认不执行任何操作，但可以创建 Thread 的子类对象，来覆盖默认行为
	
	- ## Thread 对象 start 与 run 方法的区别
	
		- 直接调用 Thread 对象的 run 方法执行方法的是主线程本身，使用 start 方法才会令开一个线程执行
	
	- ## join
	  
		- 等待线程运行结束
		  
		- `join(Long n)` 等待线程结束，最长等待 n 毫秒
		
		- 可以用于主线程需要等子线程某些操作完成后再继续的情况
	
	- ## getId()
	
		- 获取线程长整型的唯一 id
	
	- ## getName
	
		- 获取线程名称
	  
	- ## setName（String）
	
		- 修改线程的名称
	
	- ## getPriority
	  
		- 获取线程优先级
	
	- ## setPrioirty (int)
	
		- 修改线程优先级
	
	- ## getState
	
		- 获取线程状态
	
	- ## interrupt
	  
		- 打断线程，如果被打断的线程正处于 sleep，wait，join 会导致被打断的线程报错并清除 打断标记（将其设置为 false） ，如果打断的是正在运行的线程，则会设置打断标记（值为 true），park 的线程被打断也会设置打断标记
		
		- 使用 interrupt 打断线程只是将打断标记的值设置为 true，并不会直接停止线程，相当于告诉线程我想让你停止，是否真正停止需要看代码中对于打断标记变化后如何处理
		
		- 使用该方法可以打断 park 状态的线程（park 是 LockSupport 中的一个方法，效果是让线程暂停），当线程处于 park 状态时，调用 interrupt 方法可以解除 park 状态，值得注意的是，当打断标记为 true 时，调用 park 方法会立刻解除 park 状态。
	
	- ## interrupted
	  
		- 判断当前线程是否被打断，会清除打断标记
	
	- ## isInterrupted
	  
		- 判断线程运行期间是否被打断，不会清除 打断标记
	
	- ## isAlive
	
		- 判断线程是否存活
	
	- ## currentThread
	
		- 获取当前正在运行线程
	
	- ## Thread.sleep(Long n)
	  
		- 让当前执行的线程休眠，停止执行 n 毫秒，休眠时让出 cpu 给其他线程
		  
		- 在哪个线程中使用 `Thread.sleep(Long n)` 哪个线程就会进行休眠，Thread 并不是代指创建的线程变量名
		
		- 调用 sleep 方法会让线程从Running 状态变为 Timed Waiting 状态
		  
		- 其他线程此时可以使用 interrupt 方法打断线程，被打断的线程会报错（但不影响主线程）
		  
		- 睡眠结束后线程不一定会立刻执行
		  
		- 更建议使用 TimeUnit 的 sleep 方法
	
	- ## yield
	  
		- 提示线程调度器让出当前线程对 cpu 的使用，主要为了测试和调试
		
		- 调用 yield 会使当前线程从 Running 状态变为 Runnable 状态，然后执行同优先级的线程，如果没有同优先级的线程，那么不能保证让线程暂停的效果
	
	- ## 线程优先级
	  
		- 线程优先级是从 1 - 10 的整数，优先级越大抢夺到 cpu 的几率越大
		  
		- 线程优先级只是给线程调度器的一个提示，调度器可以忽略它
		  
		- 在 cpu 繁忙时，优先级高的线程会获得更多时间片，但在不繁忙时，线程优先级几乎无作用


- # 两阶段中止模式
  
	- 两阶段中止模式是一种优雅的中止一个线程的方法
	  
	- 如果使用 stop 方法会直接杀死线程，如果这时线程锁住了某些资源，当它被直接杀死后再也没机会释放锁，其他线程也不能再获取锁，该方法在高版本被废弃
	  
	- 两阶段中止模式是指再开一个线程用于监视要中止的线程的状态，在线程中进行 while true 循环，如果发现目标线程被打断，那么对目标线程进行操作，例如释放锁等，结束后跳出 while true 循环，结束自身线程，如果判断没有被打断，那么自身进行休眠，休眠结束后记录日志，如果在休眠时自身被打断，那么就需要重置打断标记，使下一次循环时结束目标线程
	  
	- 代码示例：
	```java
	class TwoPhaseTermination {
		private Thread monitor;
		
		// 启动监控线程
		public void start() {
			monitor = new Thread (() -> {
				while (true) {
					Thread current = Thread.currentThread();
					if (current.isInterrupted()) {
						log.info("料理后事");
						break;
					}
					try {
						Thread.sleep(2000);
						log.info("记录日志信息");
					}
					catch (InterruptedException e) {
						e.printStackTrace();
						current.interrupt();
					}
				}
			});
			
			monitor.start();
		}
		
		public void stop() {
			monitor.interrupt();
		}
	}
	```


- # 守护线程
  
	- 默认情况下，Java 进程需要等待所有代码都运行结束，才会结束。有一种特殊的线程叫做守护线程，只要其他非守护线程运行结束了，即使守护线程代码未执行完，也会强制结束
	  
	- 设置方法：
	```java
		Thread t = new Thread(略);
		t.setDaemon(true);
	```
	
	- 守护线程的经典用法就是作为垃圾回收器线程


- # 线程的状态
  
	- ## 操作系统层面的五种状态
	  
		- **初始状态**：仅在语言层面创建了线程，还未与操作系统线程关联
		  
		- **可运行状态**：该线程已被创建，可以由 cpu 调度执行
		  
		- **运行状态**：获取到了 cpu 时间片运行中的状态，当时间片用完会切换至可运行状态
		  
		- **阻塞状态**：调用了阻塞 API，如 BIO 时会导致线程进入阻塞状态，会导致线程上下文切换，等阻塞结束后，由操作系统唤醒阻塞的线程，转入可运行状态
		  
		- **终止状态**：线程已经执行完毕，生命周期结束，不会再转变为其他状态
	
	- ## Java API 层面的六种状态
	  
		- **NEW**：线程刚被创建，但还没有调用 start 方法
		  
		- **Runnable**：涵盖了操作系统状态的【可运行状态】、【运行状态】、【阻塞状态】
		
		- **BLOCKED、WAITING、TIMED_WAITING**：Java API 层面对阻塞状态的细分，后续会详细说明
		  
		- **TERMINATED**：线程运行结束
