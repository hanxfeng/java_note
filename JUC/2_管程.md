- # 线程上下文切换
  
	- ## 上下文切换的安全问题
	
		- 当有多个线程同时对一个变量进行操作时，可能出现下面这种问题：线程1 计算变量 a+1 的值再将值赋给 a，线程2 计算变量 a-1 的值再将值赋给 a，当线程1 计算完结果后，cpu 时间片耗尽，未能给 a 赋值，然后线程2 计算并赋值了 a-1，再将控制权转移给线程1，这时线程1 再对变量 a 进行赋值，a 此时的值就是 a+1，而不是 a。
	
	- ## 临界区
	
		- 一段代码内如果存在对共享资源的多线程读写操作，称这段代码为临界区
	
	- ## 竞态条件
	  
		- 多个线程在临界区内执行，由于代码的执行序列不同导致结果无法预测，称之发生了竞态条件


- # synchronized 对象锁
  
	- 为了避免临界区的竞态条件发生，有阻塞式和非阻塞式的两种解决方式，这里使用阻塞式的 对象锁 
	  
	- 对象锁使同一时刻至多只有一个线程能持有对象锁，其他线程想获得这个对象锁时会被阻塞住，这样就能保证拥有锁的线程可以安全的执行临界区内的代码，不用担心线程的上下文切换
	  
	- 虽然 Java 中互斥和同步都使用 `synchronized` 关键字完成，但它们有所区别：
	  
		- 互斥是保证临界区的竞态条件发生，同一时刻只能有一个线程执行代码
		  
		- 同步是因为线程执行的先后，顺序不同，需要一个线程等待其他线程运行到某个点
	
	- `synchronized` 示例：
	  ```java
		  static finla Object lock = new Object(); // 作为锁的对象，由所有线程共享
		  static int counter = 1; // 在临界区处理的共享变量
		  Thread t1 = new Thread(() -> {
			  for (int i = 0; i < 100; i++) {
			  synchronized(lock) {
				  counter++;
				  }
			  }
		  })
		  
		  Thread t2 = new Thread(() -> {
			  for (int i = 0; i < 100; i++) {
			  synchronized(lock) {
				  counter--;
				  }
			  }
		  })
	  ```
	
	- `synchronized` 实际是用对象锁保证了临界区内代码的原子性，临界区内的代码对外是不可分割的，不会被线程切换打断
	
	- 如果将 `synchronized` 放到 for 循环外，那么对象锁保护的就是这一百次循环的所有代码，等到这些代码都执行完后才会解除锁
	  
	- 如果 t1 和 t2 使用的是不同的锁对象，这种情况就相当于没有上锁
	  
	- 如果 t1 加锁，t2 不加锁，那么 t2 就不会有尝试获取对象锁的行为，会直接执行临界区代码，也和都没上锁相同
	  
	- ## synchronized 加在方法上
	  
		- ### 加在普通方法上
		  ```java
		  class Test1 {
			  public synchronized void test() {}
		  }
		  // 上面等价于
		  class Test1{
			  public void test(){
				  synchronized(this){}
			  }
		  }
		  // 直接加在普通方法上相当于锁住了 this 对象，即当前方法
		  ```
	
		- ### 加在静态方法上
		```java
		class Test2 {
			public static synchronized void test(){}
		}
		
		// 等价于
		
		class Test2 {
			public static void test() {
				synchronized(Test2.class) {}
			}
		}
		
		// 直接加在静态方法上相当于锁住了类对象
		```


- # 变量的线程安全分析
  
	- ## 成员变量与静态变量
	  
		- 如果它们没有共享（public），则线程安全
		  
		- 如果它们是共享的，那么分两种情况
		  
			- 如果只有读操作，则线程安全
			  
			- 如果有读写操作，那么需要考虑线程安全
	  
	- ## 局部变量
	  
		- 局部变量是线程安全的，局部变量是指在方法内创建的变量，不在方法间共享
		  
		- 但局部变量引用的对象未必线程安全，局部变量引用的对象指局部变量指向的堆中的对象实体。
		  
			- 如果该对象没有逃离方法的作用范围，则线程安全
			  
			- 如果该对象逃离方法的作用范围，需要考虑线程安全
	
	- `String, Integer StringBuffer` 等方法都是线程安全的，这里的线程安全是指，多个线程调用它们同一个实例的方法时，是线程安全的，可以理解为：它们的每个方法是原子的，但它们组合起来不是线程安全的
	  
	- `String, Integer` 是不可变类，是线程安全的，对 String 操作的方法是在原本 String 的基础上返回一个新的 String


- # Monitor
  
	- Monitor 被翻译为监视器或管程
	  
	- 每个 Java 对象都可以关联一个 Monitor 对象，如果使用 synchronized 给对象上锁后，该对象头的 Mark Word 中就被设置了执行 Monitor 对象的指针


- # 其他锁
  
	- 每次都使用 Monitor 锁都太过麻烦，Java 提供了其他类型的锁
	
	- ## 轻量级锁
	  
		- 使用场景：如果一个对象虽然有多线程访问但多线程访问的时间是错开的，不会竞争使用，那么就可以使用轻量级锁来优化
		  
		- 轻量级锁对使用者是透明的，即语法仍然是 `synchronized`
		  
		- ### 锁膨胀
		  
			- 如果在尝试加上轻量级锁时无法成功，当情况为已经有对象为其加上了轻量级锁时，就会进行锁膨胀，使锁从轻量级锁膨胀为重量级锁 Monitor
	
	- ## 自旋优化
	  
		- **自旋重试**是一种并发优化策略：线程不立刻挂起自己，而是在一个循环中反复检查某个条件（如锁是否已被释放、CAS 是否成功），直到条件满足为止。整个过程线程一直处于 **Runnable** 状态，就像在“原地打转”，因此得名“自旋”。
		
		- 重量级锁竞争时，可以使用自旋来优化，如果当前线程自旋成功（即这时候锁线程已经退出了同步块，释放了锁），这时当前线程就可以避免阻塞
	
	- ## 锁重入
	  
		- **锁重入**指的是：**同一个线程**在外层方法中已经获取了某个锁，当它再次请求**同一个锁**时，可以直接进入临界区，而不会被自己阻塞，同时锁的持有计数会递增。
	
	- ## 偏向锁
	  
		- **偏向锁**是 JVM 为优化**单线程重复获取同一锁**场景而引入的一种锁状态。它的核心思想是：**锁会“偏袒”第一个获得它的线程**，之后如果同一个线程再次进入同步块，无需任何 CAS 或同步操作，直接进入。
		
		- ### 撤销
		  
			- 当其他对象使用偏向锁对象时，会将偏向锁升级为轻量锁
		
		- ### 批量重偏向
		  
			- 如果对象被多个线程访问，但没有竞争，此时就会将原本线程的偏向锁撤销，将其升级为轻量级锁
			  
			- 当这个类的偏向锁撤销总次数到达阈值（20次），JVM 会触发批量重定向，对于此类中尚未发生过撤销的其他对象，允许它们直接偏向到新的线程，不再重复撤销和升级的过程
		
		- ### 批量撤销
		 
			- 当撤销偏向1锁超过阈值（40次）后，JVM 会将整个类的所有对象变为不可偏向的，之后新建的对象也是不可偏向的
	
	- ## 锁消除
	  
		- 对于不可能被共享的对象加锁时，编译器会在编译时自动将锁消除以提高性能
