
- # ThreadPoolExecutor
  
	- ThreadPoolExecutor 是 java 中的一个线程池实现类
	
	- ThreadPoolExecutor 用 int 的高 3 位表示线程池状态，低 29 位表示线程池数量，这些信息储存在一个原子变量 ctl 中，目的是将线程池状态和线程个数合二为一，这样可以用一次 CAS 原子操作进行赋值
	  
		- RUNNING，使用 111 表示，可以接收新任务，也可以处理阻塞队列中的任务，线程池刚被创建出来时就处于这个状态
		  
		- SHUTDOWN，使用 000 表示，调用线程池的 shutDown 方法（温和的关闭线程池的方法）后进入该状态，不再接收新任务，但仍然会处理阻塞队列中剩余的任务
		  
		- STOP，使用 001 表示，调用线程池的 shutDownNow 方法（粗暴的关闭方法）后进入该状态，不仅不再接收新任务，而且会抛弃掉阻塞队列中未处理的任务，打断正在执行的任务
		  
		- TIDYING，使用 010 表示，是一种过渡状态，此时的线程池任务全部执行完毕，没有活动线程，即将进入终结
		  
		- TERMINATED，使用 011 表示，线程池关闭
	
	- ## 构造方法
	  
		```java
		public ThreadPoolExecutor(
			int corePoolSize, 
			int maximumPoolSize,
			long keepAliveTime,
			TimeUnit unit,
			BlockingQueue<Runnable> workQueue,
			ThreadFactory threadFactory,
			RejectedExecutionHandler handler)
		```
		
		- corePoolSize：核心线程数，即使空闲也会保留的线程数
		  
		- maximumPoolSize：最大线程数，核心线程数+临时线程数
		  
		- keepAliveTime：临时线程的存活时间
		  
		- unit：临时线程存活时间的单位
		  
		- workQueue：任务阻塞队列
		  
		- threadFactory：线程工厂
		  
		- handler：拒绝策略
		
		- 如果队列选择了有界队列，当任务超过队列大小时，会创建救急线程（我更喜欢称为临时线程）来救急，临时线程的数量不会超过最大线程-核心线程
		  
		- 当救急线程空闲时间超过预设时间后，就会被回收已节省资源
		  
		- 如果任务数超过了最大线程数，那么就会执行拒绝策略，由 handler 指定，jdk 提供了四种拒绝策略
		
			- AbortPolicy：直接抛出 RejectedExecutionException 异常，默认的策略
			  
			- CallerRunsPolicy：让提交任务的线程自己执行该任务
			  
			- DiscardPolicy：放弃此次任务
			  
			- DiscardOldestPolicy：放弃线程池中最早的任务，执行此次任务
	
	- ## newFixedThreadPool
	  
		```java
		public static ExcutorService newFixedThreadPool(int nThreads) {
			return new ThreadPoolExecutor(nThreads, nThreads, 0L, 
				TimeUnit.MILLISECONDS, new LinkedBlockingQueue<Runnable>());
		}
		```
	- 特点：
	  
		- 核心线程数等于最大线程数，无临时线程，因此也无需超时时间
		  
		- 阻塞队列无界，可以存放任意数量的参数
		  
		- 适用于任务量已知，相对耗时的任务
	
	- ## newCachedThreadPool
	  
	- ```java
	  public static ExcutorService newCachedThreadPool(){
		  return new ThreadPoolExecutor(0, Integer.MAX_VALUE,
			  60L, TimeUnit.MILLISECONDS,
			  new synchronousQueue<Runnable>());
	  }
	  ```
	  
	- 特点：
	  
		- 核心线程数是 0,最大线程数是 Integer.MAX_VALUE，临时线程存活时间为 60s,所以它里面的线程全是临时线程，且可以无限扩展
		  
		- 使用了 synchronousQueue，没有容量，也就是说，必须有一个线程从这个队列中取消息的时候，它才会允许一个消息被放入队列，否则就要进行阻塞等待，直到有一个线程来取消息
		  
		- 适用于任务数密集，但每个任务数都比较短的情况
	
	- ## newSingleThreadExecutor
	  
		```java
		public static ExcutorService newSingleThreadExecutor() {
			return new ThreadPoolExecutor(1,1,
				0L,TimeUnit.MILLISECONDS,
				new LinkedBlockingQueue<Runnable>());
		}
		```
	
		- 希望多个任务排队执行，线程数固定为 1,任务数多于 1 时，会放入无界队列排队，任务执行完毕，这个唯一的线程也不会被释放
	  
	- ## 提交任务的相关方法
	  
		```java
		// Runnable 是一个接口，里面只有 run 一个方法，重写该方法后可以将对象提交给线程池执行
		// 执行一个没有返回值的任务，是最基础的线程命令执行方法
		void executor(Runnable command);
		
		// 提交一个带有返回值的任务，并返回一个 Future 对象，用于获取任务结果或取消任务
		<T> Future<T> submit(Callable<T> task);
		
		// 批量执行一组 Callable 任务，在不超时的情况下等待所有任务完成并返回 List<Future>
		// 如果超时则取消未完成任务
		<T> List<Future<T>> invokeAll(Collection<? extends Callable<T>> task,
			Long timeout, TimeUnit unit) throws InterruptedException
		
		// 执行一组 Callable 任务，返回的一个完成的任务的结果，此时其他任务未完成的任务取消执行
		<T> T invokeAny(Collection<? extends Callable<T>> tasks)
			throws InterruptedException, ExecutionException
		
		// 与上一个类似，但增加了超时限制，如果超时会抛出 TimeoutException 并取消所有任务
		<T> T invokeAny(Collection<? extends Callable<T>> tasks,
			Long timeout, TimeUnit unit)
			throws InterruptedException, ExecutionException
		```
	
	- ## 关闭线程池
	  
		- ### void shutdown()
		  
			- 调用该方法后，线程池不会再接收新任务，不过已提交和阻塞队列中的任务会继续执行
		
		- ### Lsit《Runnable》 shutdownNow
		  
			- 调用该方法后会结束所有线程，无论是否在执行任务 
		
		- ### boolean isShutdown()
		  
			- 查询线程池是否正在运行，如果线程池不在 RUNNING 状态，就会返回 true
		
		- ### boolean isTerminated()
		  
			- 查询线程池是否已经关闭，处于 TERMINATED 状态
	
	- ## ScheduledThreadPool
	  
		- ```java
		  // 参数代表核心线程数
		  ScheduledExecutorService pool = new Executor.newScheduledThreadPool(int n);
		  
		  // 第一个参数是匿名内部类或 lambda 表达式，表示要执行的任务
		  // 第二个参数表示任务延时执行的时间，第三个参数表示延时执行的时间单位
		  pool.schedule(()->{}, int n, TimeUnit);
		  
		  // 用于循环执行任务
		  //第一个参数是匿名内部类或 lambda 表达式，表示要执行的任务
		  // 第二个参数是任务延时执行的时间，第三个参数是循环执行的间隔，最后一个参数是时间单位
		  pool.scheduleAtFixedRate(()->{}, int n, int n, TimeUnit);
		  
		  // 用于循环执行任务
		  // 第一个参数是匿名内部类或 lambda 表达式，表示要执行的任务
		  // 第二个参数是任务延时执行的时间，第三个参数是两个任务之间的间隔
		  // 最后一个参数是时间单位
		  pool.scheduleWithFixedDelay(()->{}, int n, int n, TimeUnit);
		  ```
		  
		- 这种线程池可以延时执行任务，并且当线程中的任务出现错误时，不会影响下一个任务的执行
		  
		- 在 scheduleAtFixedRate 执行时，如果执行时间长于循环时间，中间就不会再暂停，而是不断的重新执行，scheduleWithFixedDelay 则不同，无论如何两个任务之间都会存在指定的间隔时间
		  
		- ### 指定时间执行任务（例如指定每周四 18:00 执行一次）
		  
			- 使用 scheduleAtFixedRate 方法，在延时执行参数处设置为下次周四时的时间减当前时间，在循环间隔参数处设置为一周的时间，单位取决于可接受误差
