- # MQ概述
  
	- MQ 全称 Message Queuq 消息队列，是在消息传输过程中保存消息的容器。多用于分布式系统之间进行通信。发送消息的一方称为生产者，接收消息的一份称为消费者
	  
	- ## 优势
	  
		- 应用解耦 ：耦合越低整个系统越安全，体现为消费者存活与否不影响生产者
		  
		- 异步提速 ：生产者在发送完消息后，可以进行下一步操作，不需要等待消费者回复
		  
		- 削峰填谷 ：使用 MQ 后限制消费消息的速度为 1000 这样一来，高峰期产生的数据会积压在 MQ 中，高峰被削掉了，但是因为消息积压，在高峰期过后的一段时间内，消费消息的速度还是维持在 1000，直到消息被消费完，这就是填谷。可以提高系统的稳定性
	
	- ## 劣势
	  
		 - 系统可用性降低。系统引入外部依赖越多，稳定性越差，一旦 MQ 宕机，就会对业务造成影响
		   
		- 系统复杂度提高，以前是系统间同步调用，现在是系统间异步调用。需要保证消息没用被重复消费，没用消息丢失，保证传递的顺序性，提高了复杂度。
		  
		- 一致性问题，通过 MQ 给 A，B，C 三个系统发消息，AB 处理成功，C 处理失败，如何保证消息的一致性


- # 基础概念

	- ## 整体运行流程
	  
		- Rocket MQ 主要有两部分组成，NameServer Cluster 命令服务器集群和 Broker Cluster 消息服务器集群，消息服务器集群又称经纪人，命令服务器集群记录有消息服务器集群的 IP，生产者 IP 和消费者 IP，通过心跳机制判断是否在线，当一台服务器心跳断了之后，就会认为该服务器离线，并将其从服务中移除。
		  
		- 整体流程为，生产者集群向命令集群发送消息，获取到 broker 信息，然后向 broker 发送消息并接收返回结果。在 broker 中有一个监听器，当发现 broker 中有新消息时，向消费者集群推送消息
		  
		- 流程图示：![[运行流程图示.png]]
		  
		- 生产者发送的消息主要由三部分组成：
		  代表消息主要内容的 message
		  代表消息主题的        topci
		  代表标题的               tag


- ## 单对单发送示例：
  
	- 生产者示例
```java
public void testProducer() throws Exception {
	// 建立一个生产者
	DefaultMQProducer producer = new DefaultMQProducer("group1");
	// 设置发送地址
	producer.setNamesrvAddr("Localhost:9876"); // 9876为MQ占用端口
	// 启动发送者
	producer.start();
	// 新建一个新的消息
	String msg = "hello World";
	// 发送的数据需要转为 Byte 数组
	Message message = new Message("topic1", "tag1", msg.getBytes);
	// 发送消息并获取返回值
	SendResult sendResult = producer.send(message);
	// 断开连接
	producer.shutdown();
}
```
- 消费者示例
```java
public void testConsumer () throws Exception {
	// 建立一个消费者
	DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("group1");
	// 设置接收地址
	consumer.setNamesrvAddr("Localhost:9876");
	// 设置监听的消息队列，第二个参数用于 tag 过滤和 sql 过滤
	consumer.subscribe("topic1", "*")
	// 创建一个匿名内部类，继承自MessageListenerConcurrently,处理业务流程
	consumer.registerMessageListener( new MessageListenerConcurrently(){
		@Override
		public ConsumerConcurrentlyStatus(List<MessageExt> msgs, ConsumerConcurrentlyContext context) {
			for (MessageExt msg : msgs) {
				byte[] bytes = msg.getBody();
				log.info(new String(bytes));
			}
			// 返回值只有两种，CONSUME_SUCCESS 和 CONSUME_LATER
			// 前者代表处理成功，后者代表稍后处理
			return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
		}
	});
	// 启动消费者
	consumer.start();
	// 因为消费者需要使用长连接来接收消息
	
}
```


- # 一个生产者多个消费者

	- 当一个生产者发送多条消息到 broker，有多个消费者接收这些消息，那么这些消息会被这些消费者均分后接收，这也叫负载均衡
	  
	- 假设有两个消费者，它们分别在不同组（在 java 中设置），那么它们都会收到生产者发送的所有消息
	  
	- 修改消费者模式的代码：
	```java
	// 默认的负载均衡模式
	consumer.setMessageModel(MessageModel.CLUSTERING);
	// 设置为广播模式，即同一个组中的消费者都会收到所有消息
	consumer.setMessageModel(MessageModel.BROADCASTING);
	```

- # 消息类别

	- ## 同步消息
	  
		- 向 MQ 发送消息后立刻返回成功与否
		
		- 特征：即时性较强，重要的消息，且必须有回执的消息，例如短信，通知（转账成功）
		  
	  
	- ## 异步消息
	  
		- 特征：向 MQ 发送消息后不立刻返回成功与否，而是等消息发送完后再进行返回。即时性较弱，但需要有回执的消息，比如订单中的某些消息
		  
		- 代码实现：
		  ```java
		public void testProducer() throws Exception {
			// 建立一个生产者
			DefaultMQProducer producer = new DefaultMQProducer("group1");
			// 设置发送地址
			producer.setNamesrvAddr("Localhost:9876"); // 9876为MQ占用端口
			// 启动发送者
			producer.start();
			// 新建一个新的消息
			String msg = "hello World";
			// 发送的数据需要转为 Byte 数组
			Message message = new Message("topic1", "tag1", msg.getBytes);
			// 通过匿名内部类实现方法，进而实现异步消息
			SendResult = sendResult = producer.send(new SendCallback {
				// 成功的回调方法
				@Override
				public void onSuccess(SendResult sendResult) {
					log.info(sendResult);
				}
				
				// 失败的回调方法
				@Override
				public void onExcetion(Throwable e) {
					log.info(e);
				}
			});
			// 不能断开连接，否则无法接收异步消息的回调结果
			// producer.shutdown();
	}
		  ```
	
	- ## 单向消息
	  
		- 特征：向 MQ 发送完消息后不需要回复的消息类型，例如日志消息
		  
		- 代码示例：
		```java
		
		public void testProducer() throws Exception {
			// 建立一个生产者
			DefaultMQProducer producer = new DefaultMQProducer("group1");
			// 设置发送地址
			producer.setNamesrvAddr("Localhost:9876"); // 9876为MQ占用端口
			// 启动发送者
			producer.start();
			// 新建一个新的消息
			String msg = "hello World";
			// 发送的数据需要转为 Byte 数组
			Message message = new Message("topic1", "tag1", msg.getBytes);
			// 发送单向消息并获取返回值
			SendResult = sendResult = producer.sendOneway(message);
			// 断开连接
			producer.shutdown();
		}
		```
	
	- ## 延时消息
	  
		- 特征：消息发送时并不直接发送到服务器，而是根据设定的等待时间到达，起到延时到达的缓冲作用
		  
		- 代码示例：
		```java
		public void testProducer() throws Exception {
			// 建立一个生产者
			DefaultMQProducer producer = new DefaultMQProducer("group1");
			// 设置发送地址
			producer.setNamesrvAddr("Localhost:9876"); // 9876为MQ占用端口
			// 启动发送者
			producer.start();
			// 新建一个新的消息
			String msg = "hello World";
			// 发送的数据需要转为 Byte 数组
			Message message = new Message("topic1", "tag1", msg.getBytes);
			// 设置延时等级
			message.setDelayTimeLevel(3);
			// 发送延时消息
			SendResult = sendResult = producer.send(message);
			// 断开连接
			producer.shutdown();
		}
		```
		- Rocker MQ 中对于延时不能进行很精确的设置，只能按等级进行延时，等级从1开始，1s 5s 10s 30s 1m 2m 3m 4m 5m 6m 7m 8m 9m 10m 20m 30m 1h 2h
	
	- ## 批量消息
	  
		- 特征：一次发送多条消息，节约网络开销
		  
		- 代码示例：
		```java
		public void testProducer() throws Exception {
			// 建立一个生产者
			DefaultMQProducer producer = new DefaultMQProducer("group1");
			// 设置发送地址
			producer.setNamesrvAddr("Localhost:9876"); // 9876为MQ占用端口
			// 启动发送者
			producer.start();
			// 新建一个新的消息
			String msg = "hello World";
			// 发送的数据需要转为 Byte 数组
			Message message = new Message("topic1", "tag1", msg.getBytes);
			// 将消息添加到集合中
			List<Message> listMessage = new ArrayList<>();
			listMessage.add(message);
			// 发送批量消息，send 方法可以接收所有集合类型
			SendResult = sendResult = producer.send(listMessage);
			// 断开连接
			producer.shutdown();
		}
		```
		- ### 注意
		  
			- 这些批量消息要有相同的 topic
			  
			- 这些批量消息的消息类型也应该相同
			  
			- 不能发送延时消息
			  
			- 总长度不能大于 4M


- # tag 过滤
  
	- 在`consumer.subscribe("topic1", "*")`中，第二个参数 subExpression 类似白名单，只有 tag 中带有 subExpression 中有的时，才会接收消息，例如`consumer.subscribe("topic1", "vip || svip")` 只有消息的 tag 为 vip 或 svip 时消费者才会接收这条消息

- # SQL 过滤
  
	- 可以使用 `message.putUserProperty("name", "value")` 进行消息追加属性，可以向一条消息追加多条属性
	
	- 可以将 subExpression 的类型设置为 `MessageSelector.bysql()` 根据消息属性进行过滤，语法于 SQL 一致，例如`MessageSelector.bysql("age > 16")` ，只接收属性中 age > 16 的消息。
	  
	- SQL 过滤默认是关闭的，需要在 Rocker MQ 中手动开启

- # 消息的特殊处理
  
	- ## 消息顺序
	  
		- ### 消息错乱
		  
			- mq 服务器中接收消息的是队列，假设一台服务器中现在有 3 个队列，对于一个订单消息，共有创建、付款、推送、完成四条消息，如果同时有三笔订单进来，服务器会将这12条消息随机分配到 3 个队列中，因此就可能出现，队列 1 刚读完订单 1 的创建消息，队列 3 就读到了订单 1 的完成消息，这就是消息错乱
			  
			- 核心原因是队列内有序，队列外无序
		
		- ### 使消息顺序发送的方法示例
		```java
		// 假设 orderList 中有三笔订单共十二条消息，每条消息已被转为 bytes 数组
		for (Order orderStep : orderList) {
			Message message  new Message("topic12", "tag1", orderStep);
			SendResult sendResult = producer(message, new MessageQueueSelector() {
				// 必须重写的方法，用于进行队列选择
				@Overrvide
				public MessageQueue select(List<MessageQueue> mqs, Message msg, Object arg) {
					// mqs 代表目前 MQ 服务器中的队列集合
					// 获取当前队列数
					int n = mqs.size();
					// 假设 orderStep 中有 Long 类型的订单 id 数据
					Long orderId = orderStep.getId();
					
					// 对订单 id 取余，结果作为存入的队列 id
					// 取余操作需要两边都是 int 数据，因此需要进行强转
					int i = orderId % n;
					// 返回队列
					MessageQueue messageQueue = mqs.get(i);
					return messageQueue;
					
				}
			})
		}
		
		// 消费者也需要对监听器进行修改，使用新的顺序监听器，将
		consumer.registerMessageListener( new MessageListenerConcurrently(){})
		// 改为：（匿名内部类略）
		consumer.registerMessageListener( new MessageListenerOrderly(){})
		```
	
	- ## 事务消息
	  
		- ### 流程
		  
			1. 生产者向服务器发送 half 消息
			2. 服务器收到消息后返回状态 OK
			3. 生产者在本地执行事务消息
			4. 生产者将执行成功的事务提交至服务器，失败则进行回滚
		
		- ### 事务补偿过程
		
			1. 服务器长时间未收到第 4 步结果，向生产者进行确认
			2. 生产者收到消息后对本地事务状态进行查询
			3. 根据当前事务状态决定提交还是回滚
		
		- ### 事务消息的不同状态
		  
			- 提交状态：允许进入队列，此消息与非事务消息没有区别
			  
			- 回滚状态：不允许进入队列，此消息相当于没有发送过
			  
			- 中间状态：发送了 half 消息，但未对 MQ 进行二次确认
		
		- ### 事务消息发送代码示例
		```java
	public void testProducer() throws Exception {
		// 建立一个事务消息生产者
		TransactionMQProducer producer = new TransactionMQProducer("group1");
		// 设置事务监听
		producer.setTransactionListener(new TransactionListener{
			// 正常事务处理,例如将数据存入数据库
			@Override
			public LocalTransactionState executeLocalTransactionState(Message msg, Object arg) {
				// 事务处理略
				
				// 此处有三种返回结果 COMMIT_MESSAGE，ROLLBACK_MESSAGE, UNKNOW
				// 分别对应上文的事务消息的三种状态，可以根据事务处理结果进行返回
				if (true) {  // 假设事务正常运行
					return LocalTransactionState.COMMIT_MESSAGE;
				}
				else{ // 失败后返回 UNKNOW,在事务补偿过程中检测是否执行成功
					return LocalTransactionState.UNKNOW;
				}
			}
			
			// 事务补偿过程
			@Override
			public LocalTransactionState checkLocalTransaction(MessageExt msg) {
				// 在这个函数中进行事务执行检测
				if (true) { // 虽然部分事务执行失败，但最终结果仍然可以认为执行成功
					return LocalTransactionState.COMMIT_MESSAGE;
				}
				else { // 事务执行失败
					return LocalTransactionState.ROLLBACK_MESSAGE;
				}
			} 
		})
		// 设置发送地址
		producer.setNamesrvAddr("Localhost:9876"); // 9876为MQ占用端口
		// 启动发送者
		producer.start();
		// 新建一个新的消息
		String msg = "hello World";
		// 发送的数据需要转为 Byte 数组
		Message message = new Message("topic1", "tag1", msg.getBytes);
		// 发送消息并获取返回值
		LocalTransactionSendResulr result = producer.sendInTransaction(message,null);
		// 事务执行需要时间，因此不能关闭生产者
	}
		```
