- 多级缓存多用于亿级流量

 - # 传统缓存的问题
   
	- 传统缓存策略一般是请求到达 tomcat 后，先查询 Redis，如果未命中则查询数据库。
	  
	- 以上流程处理请求要经过 tomcat 处理，tomcat 性能会成为整个系统的瓶颈
	  
	- Redis 缓存失效时会对数据库产生冲击


- # 多级缓存方案

	- 多级缓存就是充分利用请求处理的每个环节，分别添加缓存，减轻 tomcat 压力，提升服务性能
	  
	- 多级缓冲方案通常为：
	
		1. 在浏览器和客户端的本地缓存，多用于缓存静态资源
		   
		2. nginx 的本地缓存
		
		3. redis 缓存
		   
		4. tomcat 进程缓存
		   
		5. 数据库


- # JVM 进程缓存（用于 Tomcat 进程缓存）

	- ## 分布式缓存和进程本地缓存的差异
	  
		- ### 分布式缓存：
		  
			- 优点：储存量更大，可靠性更好，可以在集群之间共享
			  
			- 缺点：访问缓存有网络开销
			  
			- 场景：缓存数据量较大，可靠性要求较高，需要在集群间共享
		
		- ### 进程本地缓存
		  
			- 优点：读取本地内存，没有网络开销，速度快
			  
			- 缺点：储存容量有限，可靠性较低，无法共享
			  
			- 场景：性能要求较高，缓存数据量小

		- ### 缓存驱逐策略
		  
			- Caffeine 提供了三种缓存驱逐策略，在默认情况下，当一个缓存元素过期的时候，Caffeine 不会自动立即将其清理和驱逐，而是在一次读或写操作后，或者在空闲时间完成对失效数据驱逐。
			
			- 基于容量：设置缓存的数量上限
			  ```java
				  Cache<String, String> cache = Caffeine.newBuilder()
					  .maximumSize(1) // 设置缓存大小上限为1
					  .bulid();
			  ```
			- 基于时间：设置缓存的有效时间
			  ```java
				  Cache<String, String> cache = Caffeine.newBuilder()
					  .expireAfterWrite(Duration.ofSeconds(10)) // 设置过期时间为10秒
					  .bulid();
			  ```
			- 基于引用
			  设置缓存为软引用或弱引用，利用 GC 回收数据，性能较差不建议使用
