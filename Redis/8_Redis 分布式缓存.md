- # 单点 Redis 的问题

	- 数据丢失问题，宕机后数据消失，无法追回
	
	- 并发能力问题，单 Redis 服务器并发能力不弱，但在 618 这样的场景下仍然不足（我真的能到那种公司工作吗）
	  
	- 故障恢复问题，单 Redis 服务器，宕机后无法自动恢复
	  
	- 储存能力问题，单 Redis 服务器内存有限，因此能储存的数据也有限
  

- # RDB
  
	- RDB 全称 Redis Database Backup file （Redis数据备份文件），也叫做 Redis 数据快照，简单讲就是把内存中所有数据记录到磁盘，当 Redis 实例故障重启后，从磁盘读取文件，恢复数据
	  
	- 快照文件称为 RDB 文件，默认保存在当前运行目录
	  
	- 使用 `save` 命令进行备份，在保存过程中会阻塞所有命令
	  
	- `bgsave` 命令会开启一个子线程进行备份，避免主线程被影响
	  
	- 在正常停机时会自动进行备份
	  
	- 900 秒内至少有一个 key 被修改，则执行 `bgsave` 进行备份，300 秒内至少有十个 key 被修改，则进行备份，60 秒内有 10000 个 key 被修改则进行备份
	  
	- ## RDB 的底层原理
	  
		- 在 linux 中（因为 Redis 最开始只有 linux 端），应用不能直接操作物理内存中的数据，电脑会分配一份虚拟内存给应用，Redis 通过操作虚拟内存中的数据映射——页表来操作数据，`bgsave`  就是拷贝一份页表到子进程中，子进程根据页表将数据保存到磁盘中
		  
	- ## 缺点
		
		- RDB 执行时间长，两次 RDB 之间写入数据有丢失风险
		  
		- fork 子进程、压缩、写出 RDB 文件都比较耗时
