- # 程序计数器

	- ## 作用
	  
		- java 源代码会先转为 二进制字节码（又称 jvm 指令），jvm 指令通过解释器转为机器码，机器码再交给 CPU 执行。程序计数器的作用就是记住下一条 jvm 指令的执行地址，在物理上通过寄存器实现
	  
	- ## 特点
	
		- 不会内存溢出
		  
		- 是线程私有的，cpu 线程的执行过程是抢夺式的，当一个线程抢夺到执行权时，会分配给这个线程一定时间，当一定时间过后，如果仍未执行完，这个线程就会暂停执行，让出 cpu，然后其他线程进行争夺，让出 cpu 后，为了使下次争夺到执行权时能接着执行，就需要用程序计数器记录当前执行位置，每一个线程都有私有的程序计数器


- # 栈

	- 与数据结构-栈性质相同，都是先进后出，在 jvm 中，每个线程运行时所需要的内存称为虚拟机栈，存入栈中的元素称为**栈帧**，每个栈帧对应一个方法运行时所需要的内存，包括参数，局部变量，返回值。每个线程只能有一个活动栈帧，活动栈帧是当前正在执行的那个方法
	
	- 栈和栈帧的关系：在方法调用时，会划分一个栈帧空间，然后将栈帧压入栈中，当方法执行玩时，再将栈帧出栈
	
	- ## 问题辨别
	  
		- 垃圾回收是否涉及栈内存：不涉及，栈帧出栈后会自动回收内存，不需要使用垃圾回收进行回收
		  
		- 栈内存的分配越大越好吗：在运行 jar 包时可以通过 `-Xss` 指定栈的大小。并不是越大越好，物理内存是固定的，栈内存越大，能同时运行的线程数就越少，反而会拖慢程序运行
		  
		- 方法内的局部变量是否线程安全：
		
			- 看一个变量是不是线程安全，要看变量对多个线程是共享的还是私有的，就是说多个线程执行同一个方法，方法中的变量是否会因为方法的多次执行而出现混乱，比如方法是使输入的 x+1，但有 3 个线程同时调用，使最终结果为 x+3。
			
			- 如果一个变量，是方法内私有的，那么这个变量是线程安全的，如果是从外界输入的，就会有被别的线程访问的风险，不是线程安全的。如果这个变量最后会被 return，那么也可能被别的线程访问，就不是线程安全的。 
	
	- ## 栈内存溢出
	
		- 出现栈内存溢出的原因有栈帧过多（调用过多或递归调用，使栈帧占用的内存大于栈的内存）和 栈帧过大（方法中的变量过多，导致栈帧的大小大于栈的大小，但出现次数很少）


- # 本地方法栈

	- 在 jvm 调用本地方法（本地方法指不是由 java 编写的方法，比如 c）时使用的内存称为本地方法栈


- # 堆

	- 通过 new 关键字创建的对象都会使用堆内存
	
	- 堆是线程共享的，堆中的对象都需要考虑线程安全问题
	  
	- 堆存在垃圾回收机制，当虚拟机认为通过 new 创建的对象不会被使用后，就会自动回收这个对象占用的内存
	
	- ## 堆内存溢出
	
		- `-Xmx` 可以调整对空间大小
		  
		- 与栈类型，在堆中，如果一个对象越来越大或者对象越来越多，超过为堆分配的内存，就会出现堆内存溢出的错误
		
		- 子线程内存溢出不会影响主线程


- # 方法区
  
	- 方法区是 JAVA 虚拟机规范中规定的部分，用于保存虚拟机加载的 StringTable，常量池，类，类加载器等元数据，方法区是堆的一个逻辑部分，所有线程共享该区域，因此需要保证线程安全
	
	- java7 之前使用永久代实现方法区，方法区中的数据都保存在堆中，java8 之后使用元空间实现，方法区的数据直接保存在本地内存中
	
	- ## 内存溢出
	
		- 使用元空间实现由于使用的是系统内存，且不会为其设置最大内存，因此很难出现内存溢出的问题。使用 `-XX:MaxMetaspaceSize=` 来设置元空间最大内存
	
	- ## 常量池
	
		- 常量池就是一张表，虚拟机指令根据这张常量表找到要执行的类名，方法名，参数类型，字面量等信息，这些信息称为符号
		  
		- 运行时常量池：常量池是 `.class` 文件中的，当该类被加载，它的常量池信息就会放入运行时常量池，并把里面的符号变为真实地址
		
		- 常量池中主要储存字面量和符号引用：
		
			- 字面量：文本字符串、final 常量值、基本类型的字面量（int、long、float、double 等）
			  
			- 符号引用：类和接口的全限定名、字段的名称和描述符、方法的名称和描述符。指向 `java/lang/String` 的符号、方法 `toString()Ljava/lang/String;`
	
	- ## String Table
	
		- `javap -v *.class` 可以反编译 class 文件，获取字节码文件中的信息，包括以下三个部分：类基本信息（包括最后修改时间，MD5码，类的包名类名，父类接口等），常量池，类的方法定义（包括构造方法，被转为虚拟机指令的 java 代码），StringTable 也存在垃圾回收
		  
		- 在 1.6 版本 StringTable 在常量池中，与常量池一起保存在堆中，1.8 开始， StringTable 独立出来保存在堆中
		
		- 当执行到引用常量池中创建字符串的代码时，才会将常量池中的符号变为字符串对象，假设这个字符串为 `"a"` 此时准备好一块空间，String Table（又称字符串池，简称串池），然后将 `"a"` 作为 key 去 String Table 中去找有没有相同的 key（String Table 底层是哈希表，不能扩容），如果没有就会将 `"a"` 放入串池。每个字符串对象都是在用到时才会被创建然后放入串池中，又称为字符串延迟加载
		
		- `s1 = "a", s2 = "b", s3 = s1 + s2`的底层原理是 new 一个 StringBuilder，然后向里面添加要加的字符串，最后使用 toString 方法 new 一个新的 String 对象，因此，`s1 + s2 == "ab"` 的结果是 False，因为 `s1 + s2` 的结果保存是堆内存中（拼接的字符串最后是被 new 出来的），`"ab"` 的结果保存在 StringTable 中
		
		- 直接 `"a"+"b"` 字符串相加与变量相加不同，它的结果是保存在串池中的，所以`"a"+ "b" == "ab"` 的结果是 True，造成这一现象的原因是 javac 在编译时进行的优化，两个常量相加，代表无论如何它们的值都不会再变，因此编译时 `"a"+"b"` 会自动被修改为`"ab"` 而变量可能会被修改，因此不会被提前编译
		
		- ### intern
		
			- 在 1.8 版本中`s.intern()` 方法会尝试将字符串放入串池，如果串池中存在该字符串，则不放入，如果不存在，则放入串池，无论如何，最后都会返回串池中的对象
			  
			- 也就是说，假设 `s = "ab"` 串池中已经存在了 `"ab"` ，那么 s 就不会被放入串池中，`s == "ab"` 的结果就是 False
			
			- 在 1.6 版本中，`s.intern()` 方法会尝试将字符串放入串池，如果串池中存在该字符串，则不放入，如果不存在，则将这个对象复制一份放入串池，无论如何，最后都会返回串池中的对象
		
		- ### String Table 调优
		  
			- 可以通过 `-XX:StringTableSize= 2000` 来调整 StringTable 底层哈希表的大小，底层哈希表越大，发生哈希碰撞的几率越小，每个位置下挂的链表的长度越小，可以提高串池效率
			
			- 当需要读取大量且存在重复的字符串时，可以使用 `inrern` 方法将字符串入池，来减少堆内存压力 

- # 直接内存

	- 直接内存（Direct Memory）是指系统内存而不是虚拟机内存，常见于 NIO 操作时用于数据缓冲区，分配回收成本较高，但是读写性能高，不受 JVM 内存回收管理，也存在内存溢出问题，直接内存的内存回收由 unsafe 进行管理，在调用`ByteBuffer` 时自动进行
	  
	- 常规读取磁盘文件，需要先将文件读取至系统内存的系统缓冲区，然后再在虚拟机的堆中开辟一片内存（通常是通过 new 一个 byte 数组的形式），将系统缓冲区的数据读取至虚拟机缓冲区，然后再对数据进行操作
	  
	- 使用直接内存，会开辟出一块特殊区域，这块缓冲区系统和虚拟机都可以直接访问，因此可以提高效率
	
	- `System.gc()` 可以进行显式内存回收，即执行该代码时会触发一次内存回收，可以使用  `-XX:+DisableExplicitGc` 来禁用这种显式内存回收，但也会影响到直接内存的内存回收，只能使用 unsafe 进行手动内存回收


- # 垃圾回收

	- ## 判断垃圾
	
		- ### 引用计数法
		  
			- 如果一个对象被引用了，那么就使它的引用计数 +1，如果引用计数为 0，那么这个对象就可以被认为是垃圾进而回收掉
			  
			- 这个方法也有一个缺陷，如果两个对象互相引用，且没有其他对象引用它们，那么它们的引用计数就永远为 1，不会被回收
		
		- ### 可达性分析
		  
			- 根对象：肯定不会成为垃圾被清理的对象就是根对象
			  
			- 在这个算法执行时，会先扫描一遍所有对象，将被根对象（GC Root）直接或间接引用的对象标记出来，不进行清理
		
	- ## 五种引用
	
		- ### 强引用
		  
			- 被强引用的对象不会被回收 
		
		- ### 软引用
		  
			- 当垃圾回收发生且内存不足的情况下，软引用引用的对象会被垃圾回收
		  
		- ### 弱引用
		
			- 只要发生了垃圾回收，弱引用引用的对象都会被回收掉，弱引用与软引用都可以配合引用队列释放自身
		  
		- ### 虚引用
		
			- 虚引用多用于管理直接内存，因为直接内存无法被虚拟机管理，因此，在创建 byteBuffer 开辟直接内存时，会创建一个 Claener 虚引用对象，被虚引用引用，当 byteBuffer 被回收时，虚引用对象会被放入引用队列中，会有一个线程定时扫描虚引用队列，如果出现了新的虚引用队列，那么会调用其中的方法，回收直接内存
		
		- ### 终结器引用
		  
			- 所有的 java 对象都继承自 object 对象，其中有一个 finalize 方法（终结方法），如果一个对象重写了终结方法，且没有被强引用，那么就会被当作垃圾回收，当一个这样的对象要被垃圾回收时，先将对应的终结器引用放入引用队列中，再由一个优先级很低的线程扫描引用队列，如果有新的终结器引用，那么就会调用对象的 finalize 方法，在下一次垃圾回收时，回收这个对象使用的内存


- # 垃圾回收算法
  
	- ## 标记清除
	  
		- 顾名思义，标记清除算法分为两个阶段，分别是标记阶段和清除阶段，在标记阶段会标记要清除的对象，例如没有被引用的对象，内存不足时被软弱引用的对象等，清除阶段会释放这些对象占用的内存
		  
		- 优点：速度快。缺点：容易产生内存碎片，即回收之后的内存不连续，即使总的空闲空间是足够的，但依然无法放入较大的对象
	
	- ## 标记整理
	  
		- 第一阶段与标记清除算法第一阶段相同，在整理阶段，会在释放内存的基础上对内存进行整理，将原本分散的内存碎片整合在一起，形成一个大的空闲内存区域
		  
		- 优点：没有内存碎片。缺点：因为要移动内存中没有被释放的对象，这些对象移动时要修改相关地址，因此效率较低
	
	- ## 复制
	  
		- 复制算法将内存区域划为大小相同的两块区域，左边的区域称为 from，右边的区域称为 to，to 区域始终空闲。
		  
		- 进行回收时也是先标记要回收的对象，然后把 from 区域中不被回收的对象复制到 to 区域，在复制时进行整理，不产生内存碎片，然后清空 from 区域，再交换 from 和 to 区域
		  
		- 优点：不产生内存碎片。缺点：需要消耗双倍内存
	
	- ## 分代回收
	  
		- 在虚拟机中，不会单独使用某一种算法，而是进行综合使用。
		  
		- 在虚拟机中，堆内存被划分为两个区域，新生代和老年代，在新生代中，又分为伊甸园，幸存区 to 和幸存区 from。对于需要长时间存在的对象，将其存放在老年代中，而使用后可以丢弃的对象，存放在新生代中，这样就可以根据对象特点，选择不同的垃圾回收策略，新生代中垃圾回收更为频繁，老年代中只会在内存不足时进行垃圾回收
		
		- 对象被创建时初始会存放在伊甸园中，当伊甸园被占满时，会触发一次 Minor GC，释放一次内存，回收后，会使用复制算法，将存活的对象移动到幸存区 to 中，同时时存活的对象寿命+1（初始为0），在清理结束后交换幸存区 from 和幸存区 to
		  
		- 当后续伊甸园被占满后，会再触发一次 Minor GC，同时也会检查幸存区的对象是否需要被回收，然后执行第一次使用复制算法及之后的步骤。在幸存区的对象，如果经历的垃圾回收次数超过一个阈值，默认是 15，就会将其转移到老年代中
		  
		- 当伊甸园，幸存者 from 和老年代的内存都被占满时，会触发一次 Full GC，对所有内存进行一次清理

- # 垃圾回收器
  
	- 垃圾回收器分三种，串行、吞吐量优先、响应时间优先
	  
	- ## 串行
	  
		- 串行的垃圾回收器执行垃圾回收时会暂停其他线程，底层是单线程的
		  
		- 适用于堆内存较小的情况
	
	- ## 吞吐量优先
	  
		- 吞吐量优先的垃圾回收器是多线程的
		  
		- 适合堆内存较大的情况，需要使用多核 cpu
		  
		- 让单位时间内 SWT（进行垃圾清理时其他线程暂停的时间） 的时间最短
	
	- ## 响应时间优先
	
		- 响应时间优先的垃圾回收器是多线程的
		  
		- 适合堆内存较大的情况，需要使用多核 cpu
		  
		- 响应时间优先的垃圾回收器会尽可能让单次垃圾回收 SWT（进行垃圾清理时其他线程暂停的时间） 最短
	
	- ## 响应时间优先与吞吐量优先的差异
	  
		- 响应时间优先是指单次垃圾回收时间最短，吞吐量优先是指一定时间内进行垃圾回收的时间最短，无论多少次。
		  
		- 举例讲就是响应时间优先是一小时内进行 5 次垃圾回收，每次时间都是 0.1s，而吞吐量优先是一小时内进行了 2 次垃圾回收，两次都是 0.2 秒，总花费时间 0.4<0.5
	
	- ## 串行垃圾回收器
	  
		- 开启串行垃圾回收器的参数：`-XX:+UseSerialGC= Serial + SerialOld`。
		  
		- 串行垃圾回收器分为两个部分，Serial 运行于新生代，使用复制算法进行垃圾回收，SerialOld 运行于老年代，使用标记整理算法进行垃圾回收
		  
		- 当启动垃圾回收时，正在运行的线程会到一个安全点停下，然后串行垃圾回收器会阻塞其他线程，只留一个线程进行垃圾回收
	
	- ## 吞吐量优先垃圾回收器
	  
		- 开启参数：`-XX:+UseParallelGC ~ -XX:+UseParalleOldGC` 这两个参数开启其中一个另一个会自动开启，同样是 ParallelGC 运行于新生代，ParalleOldGC 运行于老年代 
		  
		- 当启动垃圾回收时，正在运行的线程会到一个安全点停下，然后吞吐量优先垃圾回收器会使用所有线程进行垃圾清理
		  
		- ### 相关参数
		  
			- `-XX:ParallelGCThreads=n` ：用于设定垃圾清理时使用的线程数
			
			- `-XX:UseAdaptiveSizePolicy`：添加此参数后会动态调整包括新生代大小，堆大小，晋升阈值等的数值
			  
			- `-XX:GCTimeRatio=raito`：这个参数用于调整垃圾回收所占用的最大时间，计算公式为 $1/1+ratio$ ，即 ratio = 99 时，垃圾回收所占时间不能超过 1%，吞吐量优先垃圾回收器会调整堆等的大小以实现这个目标，通常是增大堆以减少垃圾回收次数
			  
			- `-XX:MaxGCPauseMillis=ms`：这个参数用于调整单次垃圾回收时阻塞其他程序的时间，默认为 200ms，为了实现这个目标，会调整堆等的大小实现这个目标，通常与上一个参数冲突，因为减少单次耗时需要减少堆大小
	
	- ## 响应时间优先垃圾回收器
	  
		- 开启参数：`-XX:UseConcMarkSweepGC ~ -XX:UseParNewGC ~ SerialOld` 并发的，基于标记清除的垃圾回收器，并发是指垃圾回收和程序并行执行，吞吐量的并行执行是指所有线程都进行垃圾回收。参数含义是指，对于老年代，使用 CMS 进行垃圾回收，对于新生代，使用基于复制算法的垃圾回收，当 CMS 出现问题时，退化到串行垃圾回收器进行垃圾回收
		
		1. 当启动垃圾回收时，所有线程会在安全点停下，CMS 会单线程的进行初始标记，此时其他线程是阻塞的。
		2. 标记完成后用户线程可以继续执行，CMS 会并发进行标记，标记剩余垃圾。
		3. 完成后用户线程会在安全点停下，因为之前进行标记时用户线程在继续执行，因此 CMS 会进行重新标记，找出新增或减少的垃圾，此时所有线程用于重新标记。
		4. 重新标记后 CMS 会并发进行清理
		  
		- ### 相关参数
		  
			- `-XX:ParallelGCThreads=n ~ -XX:ConcGCThreads=threads`：第一个参数是指进行垃圾处理的线程数，通常与 cpu 核数相同。后一个参数是指在第四步中进行垃圾回收的线程数，通常为前一个参数的四分之一
			  
			- `-XX:CMSInitiationgOccupancyFraction=percent` ：因为是并发进行垃圾清理的，因此会在垃圾清理时产生新的垃圾，这些垃圾称为浮动垃圾，浮动垃圾要等到下次进行垃圾清理时才会被清理掉，因此 CMS 不会在内存完全占满后再进行垃圾清理，而是在内存占比超过一定比例后进行，这个参数就是控制内存占比超过多少后进行垃圾回收，例如当值为 80 时，占比超过 80% 就会触发垃圾回收
			  
			- `-XX:+CMSScavengeBeforeRemark`：启用这个标记之后，在重新标记之前会对新生代进行一次垃圾回收。因为重新标记要扫描新生代是否有引用老年代的对象，在重新标记前清理一次新生代可以减少扫描时间


- # Garbage Frist

	- 简称 G1，是一种垃圾回收器，jdk9 后的默认垃圾回收器，替代了 CMS
	  
	- 注重吞吐量和低延迟，默认暂停目标是 200ms。适合于超大堆内存，会将堆划分为多个 Region。整体上是标记整理算法，两个区域之间是复制算法
	  
	- ## 相关参数
	  
		- `-XX:UseG1GC`：启动 G1 垃圾回收器
		  
		- `-XX:G1HeapRegionSize=size`：设置 Region 区域大小
		  
		- `-XX:MaxGCPauseMillis=time`：设置最大暂停时间
	
	- ## 进行垃圾回收的三个阶段
	
		- 分布是 Young Collection 、Young Collection+CM 和Mixed Collection，这三个阶段轮流执行，从 Young Collection 开始
	
	- ## Young Collection 阶段
	  
		- 伊甸园内存满后后进行垃圾清理，剩余的对象会被拷贝到幸存区，幸存区中超过阈值的对象会被转移到老年代。（对，就是和分代回收一样）
	
	- ## Young Collection+CM 阶段
	  
		- 在 Young Collection GC 时会进行 GC Root 的初始标记
		  
		- 老年代占用堆比例达到阈值后，进行并发标记（不 STW），阈值由以下参数控制：`-XX:InitiatingHeapOccupancyPercent=percent` 默认为 45%
	  
	- ## Mixed Collection 阶段
	  
		- 这个阶段会对伊甸园区，幸存区，老年代进行全面垃圾回收
		  
		- 回收时使用分代回收算法，对于老年代，使用复制算法进行垃圾回收，进行垃圾回收时，会根据最大暂停时间有选择的进行回收，会选择释放空间较多的对象进行回收
	
	- ## Young Collection 跨代引用
	  
		- 跨代引用是指老年代引用了新生代的对象，在进行垃圾清理时要寻找根对象和根对象引用的对象，因为一部分根对象是老年代中的，而老年代因为存活对象多，逐个扫描耗时较长
		  
		- 为了解决这个问题，G1 将老年代分为多个区域，称为卡表，每个区域称为卡表，每个卡的大小是 512k，如果一个卡中有对象引用了新生代的对象，那么这个卡被称为脏卡，这样扫描时只关注脏卡即可
	
	- ## Remark 重标记
	  
		- 在标记时，对象有三种状态，黑色的处理完毕，灰色的正在处理，白色的未处理。处理后的对象有两种状态，黑色的被引用和白色的不被引用
		  
		- 在并发标记时，一个对象因为不被引用时被标记为了白色，但在重标记之前，它被引用了，这时就会触发写屏障，当对象引用发生改变时，就会触发写屏障
		  
		- 当写屏障触发时，就会将被引用对象 C 加入队列中，然后把 C 变成灰色的待处理状态，等到并发标记结束，进入重新标记阶段时，就会对队列中的对象进行处理
	
	- ## 字符串去重
	  
		- 在启用 G1 时，会将所有新增的字符串对象放入一个队列，当触发新生代垃圾回收时，会并发进行检查是否有字符串重复，如果存在字符串重复，则让它们引用同一个 `char[]` 
		  
		- 与 `String.intern()` 不同， `String.intern()`关注的是字符串对象，字符串去重关注的是 `char[]`，在 JVM 内部，两者使用不同的字符串表
		  
		- 优点是节省大量内存，缺点是略微增加 cpu 消耗和新生代垃圾回收时间
	
	- ## 类卸载
	  
		- 所有对象经过并发标记后，就能知道哪些类不再使用，当一个类加载器的所有类都不再使用，则卸载它加载的所有类
	
	- ## 回收巨型对象
	  
		- 当一个对象大小超过 regio 一半时，称为巨型对象
		  
		- 巨型对象不会进行拷贝，回收时会优先考虑巨型对象
		  
		- G1 会跟踪老年代所有 incoming 引用，当巨型对象的老年代 incoming 引用为 0 时，就会在新生代的垃圾回收中被回收掉


- # GC 调优
  
	1. 确定目标，需要**低延迟**还是**高吞吐量**，互联网重新需要低延迟，科学计算类程序需要高吞吐量
	2. 选择合适的垃圾回收器。低延迟可选的垃圾回收器有 CMS，G1，ZGC，高吞吐量可选的垃圾回收器有 ParallelGC
	   
	- ## 从代码层面减少 GC 发生
	
		- 查看数据是不是太多，例如查询 MySQL 中的大表，导致大量无用数据堆积在 java 内存中
		  
		- 数据是否太过臃肿，例如查询数据时，只需要姓名数据，但把年龄数据一同保存到堆内存中。包装类的内存占用要远大于普通类，减少不必要的包装类
		  
		- 检查内存是否泄露，进行缓存时使用第三方缓存
	
	- ## 新生代内存调优
	  
	- TLAB：每一个线程，都会在伊甸园中分配一块私有的区域，称为 TLAB，当 new 一个对象时，会首先检查 TLAB 缓冲区是否有内存
	  
	- 当 new 一个对象时，首先会在1伊甸园进行分配，分配速度非常非常快
