
- # 语法糖
  
	- 所谓语法糖，就是指 java 编译器把 java 源码编译为字节码的过程中，自动生成和转换的一些代码，主要是为了减轻程序员负担。
	
	- ## 默认构造器
	  
		- 如果在源码中没写任何构造方法，编译为字节码后也会自动的加上一个无参构造方法
	
	- ## 自动拆装箱
	  
		- 自动拆装箱是指自动在包装类和基本类之间相互转换，例如可以直接将一个 Integer 类型的变量赋值给 int。
	
	- ## 泛型
	  
		- java 中的泛型是指：例如在 spring 项目中的返回对象 R，源码中返回的是 `R<T>`这样的数据，其中的 T 就是泛型
		
		- JVM 中的泛型是指在编译时，编译器会将泛型信息抹除掉，替换为 Object，例如`List<String>` 在编译后会变成 `List<Object>` ，这一行为被称为类型擦除。
		  
		- 当从 `List<Object>` 中获取元素时，编译后的文件会执行类型转换 `Integer x = (Integer)list.get(0);`
		  
		- 引入泛型是为了：
			- **类型安全**：在编译时检查集合等容器中元素的类型，避免运行时 `ClassCastException`。
			  
			+ **消除强制转换**：减少代码中显式的类型转换
		
		- 类型擦除擦除的是字节码上的泛型信息，但是 LocalVariableTypeTable 中会保存有原本的泛型信息，使用反射仍然能获取这些信息
	
	- ## 可变参数
	  
		- 可变参数链接：[[11_集合进阶#可变参数]]
		  
		- 在编译时，编译器会根据传入的参数数量自动生成对应长度的数组，然后将参数放入数组中
		  
		- ![[可变参数.png]]
	
	- ## 数组赋初始值
	  
		- 可以像 `int [] array = {1,2,3}` 这样为数组赋初值，编译后代码为：`int [] array = new int[]{1,2,3}`
	
	- ## 增强 for 循环
	  
		- 编译时会自动将增强 for 循环改写为普通 for 循环
	  
	- ## switch 字符串
	  
		- switch 原本是不支持字符串和枚举类的，但在 jdk7 开始，通过语法糖支持了字符串和枚举类
		  
		- ### 字符串 switch
		```java
		// 源代码
		switch (str) {
			cache "hello" :{
				print("h");
				break;
			}
			cache "world":{
				print("w");
				break;
			}
		}
		
		// 编译后的代码
		btte x = -1;
		switch(str.hashCode()){
			case 99162332 : { // 99162332 是 hello 的hashCode
				if (str.equals("hello")) {
					x = 0;
				}
			}
			case 113318802 : { // 113318802 是 world 的 hashCode
				if (str.equals("world")) {
					x = 1;
				}
			}
		}
		
		switch (x) {
			case 0 :{
				print("h");
				break;
			}
			case 1 :{
				print("w");
				break;
			}
		}
		```
		
		- 可以看到，编译后执行了两边 switch，第一遍根据字符串的 hashCode 和 equals 将字符串转换为相应的 byte 类型。第二遍才用 byte 进行比较执行
		  
		- 第一遍即使用 hashCode 又使用 equals ，使用 hashCode 是为了提高效率，使用 equals 是为了防止哈希冲突
		  
		- ### 枚举 switch
		```java
		// 枚举类
		enum Sex{
			MALE, FEMALE
		}
		
		// 源码
		switch (sex) {
			case MALE :{
				print("男");
				break;
			}
			case FEMALE:{
				print("女");
				break;
			}
		}
		
		// 编译后代码
		// 定义了一个合成类，仅 JVM 使用，对程序员不可见。用于映射枚举的 ordinal 与数组元素 	
		// 的关系，枚举的 oridinal 表示枚举对象的序号，从 0 开始，即 MALE 的 ordinal() = 0
		// FEMALE 的 ordinal() = 1
		static class $map {
			// 数组大小为枚举元素个数，里面储存 case 比对用的数字
			static int[] map = new int[2]; 
			static {
				map[Sex.MALE.oridinal()] = 1;
				map[Sex.FEMALE.oridinal()] = 2;
			}
		}
		
		// 编译后代码
		int x = $MAP.map[sex.oridinal()];
		switch(x) {
			case 1:{
				print("男");
				break;
			}
			case 2:{
				print("女");
				break;
			}
		}
		```

	- ## try-with-resources
	  
		- 使用`try(资源变量 = 创建资源对象) [] catch(){}` 可以不用写 finally 语句，编译器会帮忙加上 finally 部分的代码，关闭资源
	  
	- ## 方法重写时的桥接方法
	  
		- 方法重写时的返回值分两种情况：1.父子类的返回值完全一致。2.子类的返回值类型是父类的子类的一种
		  
		- 当情况为 2 时，编译器会重写一个方法，这个方法的返回值与父类相同，在这个方法中调用子类方法
	
	- ## 匿名内部类
	  
		- ### 没有引用局部变量的匿名内部类
		  
			- 这种匿名内部类在编译时会将匿名内部类摘出来，单独写成一个类，在原本的地方 new 这个类
		
		- ### 引用了局部变量的匿名内部类
		  
			- 这种匿名内部类会生成一个变量和一个构造方法，要求在 new 这个类时将引用的局部变量输入，其余与上相同


- # 类加载
  
	- ## 加载阶段
	  
		- 加载阶段是类加载的第一步，主要将类的字节码载入到方法区中，载入方法区中的数据使用 C++ 的instanceKlass 来描述 java 类。里面最重要的字段是 `_java_mirror`即 Java 的镜像类，作用是把 klass 暴露给 java 使用（虚拟机无法直接调用 c 中的方法），相当于 java 和 c 之间的桥梁
		  
		- 如果类的父类没有加载，会先加载父类。加载和后续的连接是交替运行的
		  
		- 图示：![[加载示例.png]]
	  
	- ## 验证阶段
	  
		- 主要验证类是否符合 JVM 规范，由四个阶段组成
		  
		  1. 文件格式验证（Class 文件格式检查）
		  2. 元数据验证（字节码语义检查）
		  3. 字节码验证（程序语义检查）
		  4. 符合引用验证（类的正确性检查）
	
	- ## 准备阶段
	  
		- 为 static 变量分配空间，设置默认值
		  
		- static 变量分配空间和赋值是两个步骤，分配空间在准备阶段完成，赋值在初始化阶段完成
		  
		- 如果 static 变量是 final 类型或是字符串常量，那么编译阶段值就确定了，赋值在准备阶段完成
		  
		- 如果 static 变量是 final 的，但属于引用类型，那么赋值也会在初始化阶段完成
