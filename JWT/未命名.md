- # 什么是 JWT
  
	- 全程 JSON WEB TOKEN 通过数字签名的方式，以 json 对象为载体，在不同服务终端之间安全的传递信息


- # JWT 的作用
  
	- JWT 常用于授权认证，一旦用户登录，后续的每个请求都包含 JWT，系统在每次处理用户请求前，都要先进行 JWT 安全校验，通过后再进行其他处理


- # JWT 组成
  
	- JWT 由三部分组成，以 . 进行分割
	  
		- 第一部分：Header （头部）
		  
			- 该部分由两部分组成，分别是令牌的类型和使用的签名算法，示例如下：
			```json
			{
				"typ": "JWT",  // 令牌类型
				"alg": "HS256" // 签名算法
			}
			```
		
		- 第二部分：Payload （载荷）
		  
			- Payload 中数据以键值对方式存在，每一个键值对被称为一个 Claim 声明，声明通常分为三类：
			  
				- 注册声明
				
					- 这部分声明由官方预定义，推荐使用以增加系统间互操作性，但不强制要求使用
					  
					- 这一部分建议至少要传递两个键值对：sub 和 exp，分别存放用户的唯一标识 id 和 过期时间
				
				- 公共声明
					- 为避免与已有标准冲突，官方建议使用 **URI（统一资源标识符）** 作为键名
				  
				- 私有声明
					- 实际开发中最常用的部分，是服务端和客户端自定义的键值对，用于传递数据，例如 userId, userName 等数据
			
			- 需要注意的是，不要在 Payload 中存放敏感数据，例如密码，个人身份信息等，这部分使用 Base64 进行编码，但没有加密，相当于明文传输
			  
			- 不要放入太多数据，JWT 通常在 HTTP Header 中传输，要求大小不超过 16 kb
		
		- 第三部分：Signature（签名）
		  
			- 这部分用于验证令牌的完整性和真实性，防止数据被篡改，它将编码后的 Header、编码后的 Payload 以及一个 Secret （密钥）通过 Header 中指定的算法进行哈希运算后生成的字符串
